# 09-25 параллель кезек: өлшеу шеберінің өзегі

Бұтақ: `codex/0925-par`. Негізгі ағашқа, UI-ға, браузерге және e2e-ге өзгеріс жасалған жоқ.

## Орындалды

- `src/core/measure/index.ts`: төрт қабырға/бұрыш, әр қабырғадағы розетка, құбыр, батарея, желдеткіш, терезе алды және плитка қалыңдығы; «бар/жоқ» жауабы мен фото сілтемесін тексеру. Әр санның көзі (`manual`/`voice`/`laser`) және уақыты сақталады.
- Толық тікбұрышты өлшемді `Room` және `KitchenOptions` кірісіне түрлендіру; кедергілер мен бастапқы қабырға картасы қосымша беріледі. Қиғаш бұрыш не қарама-қарсы қабырға айырмасы үнсіз дөңгелектелмейді.
- Шкафтар мен КП-ға ықтимал әсерді есептеу; кедергі орны белгілі болса, қиылысатын шкафтар ғана белгіленеді.
- `measurement.upsert` әрекеті қолдағы `SyncQueue` үшін дайындалады. Аяқталмаған өлшем офлайн кезекте сақталып, желі келгенде жіберілуі тесттелді.
- `docs/measure-wizard-core.md`: қолдану жолы және қазіргі шектеулер.

## Тексеру

- TDD: бастапқы нысаналы Vitest модуль жоқ кезде қызыл; кейін 9 тест жасыл.
- `NODE_OPTIONS=--max-old-space-size=2048 npx vitest run tests/measure.test.ts --maxWorkers=2` — 9/9 өтті.
- `npm run -s typecheck` — өтті.
- Мутация: жауапсыз кедергіні тексеретін шарт уақытша өшірілді; тиісті тест құлады. Код `/tmp` ішіндегі `cp` көшірмесінен қалпына келтіріліп, тест қайта өтті.

## UI кейін

- Фото файлдарының байтын IndexedDB-де сақтау және `photoRef` бойынша серверге жіберу осы өзекке кірмейді. Әрекеттің өзі JSON және офлайн кезекке жарайды.
- Ас үй генераторы өз `room` мәнін жасайды; UI/интеграция `toKitchenInput.room` мәнін жобада қолдануы және `wallMap` арқылы орындарды сәйкестендіруі керек.
- Кедергілер бойынша шкафтарды автоматты жылжыту жасалмаған; модель өзгеріске ұшырайтын шкаф/КП-ны ғана көрсетеді.
