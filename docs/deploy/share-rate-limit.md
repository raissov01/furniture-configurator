# Share кодын қорғау

VPS-та `lib/server/rateLimit.ts` барлық Node процесіне ортақ SQLite файлын қолданады.
`DATA_DIR` тұрақты әрі ортақ томға бағытталсын. Қате share кодын бір IP-ден
сағатына 20 реттен, сол IP мен бір код жұбын 5 реттен артық тексеруге болмайды;
бір IP бір share-ге минутына ең көбі 5 пікір жазады. Лимитке жеткенде API 429
қайтарады. Клиент IP-і `X-Real-IP` арқылы алынады: nginx бұл тақырыпты
**өзі қайта жазуы** керек, клиент жіберген мәнді қабылдамауы керек.

nginx деңгейіндегі қосымша қорғаныс мысалы:

```nginx
limit_req_zone $binary_remote_addr zone=share_codes:10m rate=20r/m;
location /api/share/ {
    proxy_set_header X-Real-IP $remote_addr;
    limit_req zone=share_codes burst=10 nodelay;
    proxy_pass http://127.0.0.1:3000;
}
```

Бұл nginx шегі API-дің сағаттық есептегішінің орнына жүрмейді.

Vercel-де қазіргі cloud маршруты `cloudOff()` арқылы 503 қайтарады, себебі
жобаның SQLite сақтау жүйесіне ортақ тұрақты диск берілмеген. Сондықтан
Vercel-де share кодтары белсенді емес. Оны белсендіру үшін **жоба дерегін де,
rate limit есептегішін де** ортақ тұрақты қоймаға көшіру қажет; әр function-ның
жергілікті SQLite файлы қауіпсіз лимитті қамтамасыз етпейді.
