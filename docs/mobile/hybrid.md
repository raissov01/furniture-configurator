# AisMebel Android: гибрид қосымша (1.1)

## Не істейді

- **Интернет бар:** WebView сервердегі толық мобайл нұсқаны (`/mobile`) ашады: аккаунтқа кіру, Бүгін, тапсырыстар, КП, клиент коды, монтаж, QR скан, синхрон — сайттағымен бірдей код.
- **Интернет жоқ (не сервер жауап бермесе):** қосымша ішіне салынған офлайн өлшеу беті ашылады (`native/NativeMeasurementApp.tsx` + ортақ `MeasurementWizard`). Онлайн ғана жұмыс істейтін бөлімдер «Интернет арқылы жұмыс істейді» белгісімен көрсетіледі.
- **Байланыс оралғанда:** офлайн өлшемдер кірген пайдаланушының аккаунтына бар синхрон кезегі арқылы жіберіледі.

## Сервер мекенжайы

Бір ғана build-time айнымалы: `AISMEBEL_APP_URL` (әдепкі — staging `https://mebel-test.85.137.91.47.sslip.io`). Тек `https`. Жол берілмесе бастапқы бет `/mobile`.

```bash
AISMEBEL_APP_URL=https://mebel.balu-fit.com npm run cap:sync   # прод
```

`capacitor.config.ts` (`resolveHybridTarget`) пен `native/vite.config.ts` екеуі де осы айнымалыны оқиды: біріншісі WebView-ге, екіншісі офлайн беттің «Толық нұсқаны ашу» сілтемесі мен денсаулық тексеруіне (`/api/v1/health`).

**Маңызды:** хостты ауыстыру = басқа origin = басқа IndexedDB. Staging жинағында жиналған, әлі жіберілмеген офлайн өлшемдер прод жинағын орнатқаннан кейін көрінбейді. Жаңартудан бұрын кезек бос болсын (`/mobile` жолағында «Ожидает отправки: 0»).

## Архитектура және неге осылай

Негізгі мәселе — origin. Жергілікті Capacitor беті `https://localhost`, сайт `https://<хост>`: cookie, localStorage, IndexedDB бөлек. Офлайн өлшемді аккаунтқа жеткізу үшін оны не origin арасынан тасу керек, не origin-ді біреу ету керек.

Таңдалған жол — **бір origin**:

```ts
server: {
  url: 'https://<хост>/mobile',          // онлайн: сервердегі толық нұсқа
  hostname: '<хост>',                     // жергілікті ассеттер де сол хост атымен
  errorPath: 'aismebel-offline.html',     // желі/сервер қатесінде осы бет
  allowNavigation: ['<хост>'],
}
```

Capacitor (`Bridge.getErrorUrl`) қате бетін `https://<hostname>/<errorPath>` мекенжайымен ашады, ал `WebViewLocalServer` дәл осы URL-ды APK ішінен береді. `hostname` сервер хостымен бірдей болғандықтан, офлайн бет **сайттың өз origin-інде** жұмыс істейді:

- IndexedDB `tapsyrys-mobile` (өлшемдер, фото, `actions` журналы) толық `/mobile`-мен ОРТАҚ;
- сессия cookie де ортақ — CORS, токен, postMessage қажет емес;
- синхрон протоколы өзгермейді: `SyncQueue` (`src/core/sync`), `createMobileSyncTransport` (`lib/mobile/syncTransport.ts`), `POST /api/mobile/photos/:id` + `POST /api/mobile/measure/sync` (идемпотентті action ID, ревизия, қайшылық).

Тек бір URL жергілікті берілетіндіктен, офлайн бет JS пен CSS ішіне салынған **бір HTML файл** болып жиналады (`native/vite.config.ts`, `aismebel-inline-offline-page` плагині). Беттің `/assets/*` сұраулары желіге кетпейді.

Қаралған баламалар:

| Жол | Неге емес |
|---|---|
| Жергілікті қабық + cross-origin API (`credentials: 'include'`, CORS) | Android WebView үшінші тарап cookie-ін әдепкі бұғаттайды; `SameSite=None` + CORS + CSRF серверді өзгертеді. |
| Жергілікті қабық + жеке мобайл токен | Жаңа auth ағыны, токен сақтау/жаңарту, серверде жаңа endpoint — «жаңа протокол ойлап таппа» талабына қайшы. |
| Remote бетке postMessage/URL арқылы тапсыру | Навигация терезені ауыстырады (postMessage-ке ортақ терезе жоқ); фото 8 МБ-қа дейін — URL-ға сыймайды. |
| Service worker офлайн кэш | Алғашқы іске қосу офлайн болса кэш бос; SW жаңарту/инвалидация күрделі. `errorPath` бірінші іске қосуда да жұмыс істейді. |

## Офлайн → онлайн синхрон

1. **Офлайн бет** өлшемді сақтағанда `saveOfflineMeasurement` (`components/mobile/offlineHandoff.ts`): черновик `putSurvey`, сосын `enqueueLatestMeasurement` → `actions` журналында `pending` әрекет. Кезектің `network` күйі ешқашан `online` болмайды — бұл бет желіге ештеңе жібермейді.
2. Офлайн бет әр 15 с `GET /api/v1/health` тексереді. Сервер жауап берсе және пайдаланушы өлшеу шеберінде болмаса, `/mobile`-ге өтеді (`offlineShellNext`). Сервер `/mobile`-ге қате берсе, `errorPath` қайта офлайн бетке әкеледі — цикл болмас үшін автоматты өту 60 с ішінде қайталанбайды (`sessionStorage`). Қолмен «Толық нұсқаны ашу» батырмасы әрқашан бар.
3. **`/mobile`** ашылғанда бұрынғы логика: `queue.setOnline(true)` — `pending` әрекеттер фото → өлшем ретімен сессия cookie-імен кетеді; кейін өңделген черновиктер `reconcile` арқылы кезекке түседі.
4. **Кірмеген болса** сервер 401 береді → әрекет `rejected`, себебі «Кіру қажет» (дерек жоғалмайды). Пайдаланушы кіріп `/mobile`-ге оралғанда, `/api/me` рөлді (owner/designer) растағаннан кейін `authRetryCandidates` осындай әрекеттерді бір рет автоматты `retryRejectedMeasurement` арқылы қайта жібереді. Қолмен «Повторить отправку» да қалады.
5. Қайшылық (сервердегі басқа нұсқа) бұрынғыдай `/mobile`-де «Оставить мою / серверную» арқылы шешіледі.

## Android қабығы

- **Артқа:** `MainActivity` алдымен `window.aismebelBack()` ілмегін шақырады (`lib/mobile/nativeBack.ts`; өлшеу шебері → тізім), сосын WebView тарихы, болмаса шығу. Офлайн беттен тарихпен артқа жүрілмейді (алдыңғы жазба — жүктелмеген бет, ол қайта осында әкелер еді).
- **Сыртқы сілтемелер:** өз хостымыздан басқа кез келген навигация (Kaspi, WhatsApp, `tel:`) Capacitor `launchIntent` арқылы жүйелік браузерде/қосымшада ашылады.
- **Камера:** `CAMERA` рұқсаты манифестте; `getUserMedia` сұрауын `BridgeWebChromeClient.onPermissionRequest` Android рұқсатына айналдырады; фото `<input type=file>` Capacitor файл таңдағышы арқылы. `android.hardware.camera` `required=false`.
- Нұсқа: `versionCode 2`, `versionName 1.1`.

## Шектеулер

- 1.0 нұсқасы (`https://localhost` origin) жинаған өлшемдер 1.1-де көрінбейді — басқа origin, ал 1.0-де серверге жіберу болмаған. 1.0 қолданушылары жаңартудан бұрын өлшемдерді қолмен көшіріп алуы керек.
- Capacitor HTML құжаттарды натив прокси арқылы алады (`handleProxyRequest`): сервердің жауап тақырыптары (CSP т.б.) құжатқа жетпейді, құжат әрдайым 200 болып беріледі; 4xx/5xx құжат `errorPath`-қа әкеледі.
- WebView файл жүктеп алуды (PDF экспорт т.б.) өздігінен өңдемейді — нақты телефонда тексеру керек.
