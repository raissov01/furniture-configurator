# Базис-Мебельщик 2023All — материалдар импорты

Дереккөз: `2023All.xlsx` (33 554 жол × 36 баған, талдауы `docs/basis/materials-db.md`-де).
Мұнда — сол талдаудан кейінгі НАҚТЫ ИМПОРТ: не алынды, не тасталды, неге, және
баға/`hasGrain` бойынша қабылданған шешімдер.

Конвейер (қайта жүргізу үшін `npm run import:basis`, бастапқы `2023All.xlsx`
файлы қажет — ол репода жоқ, тек шикі деректің сүзілгені committed):

```
2023All.xlsx  ──(scripts/basisExtract.py, openpyxl стрим)──►  docs/basis/basis-filtered-raw.json
                                                                           │
                                                     scripts/importBasis.mjs
                                                                           ▼
                          src/core/data/generated/{basisMaterials,basisEdgeBands,basisPriceMeta}.json
                                                                           │
                                                    src/core/data/basisCatalog.ts (типтеу)
                                                    src/core/data/basisPriceMeta.ts (типтеу)
```

`SEED_CATALOG` (`src/core/seed.ts`) ӨЗГЕРТІЛМЕДІ. Бұл — қосымша, бөлек каталог:
`BASIS_CATALOG` / `BASIS_MATERIALS` / `BASIS_EDGE_BANDS` (`src/core/index.ts`
арқылы экспортталады). Пайдаланушы қажет болса екеуін қолмен біріктіреді.

Тапсырмада берілген «тек ЛДСП + кромка + ХДФ/МДФ, қалыңдығы 16/18/3/4» сол

  қазіргі домені (корпустық жиһаз) оларды қажет етпейді — қосымша импорт

  таңдағышын бітейді.
- **ХДФ 3/4 мм.** Арт қабырғаға (§4.5) толық сәйкес, базада тек осы екі

- **Кромка — ені 19/22 мм ғана.** `EdgeBand` типінде (`types.ts:62`) ЕНІ

  ал бізге бір-ақ керек. **19 мм — 16 мм қалыңдыққа, 22 мм — 18 мм-ге**
  сәйкес келетін цех стандарты (қалыңдық + ~3 мм), сондықтан дәл осы екі ен
  таңдалды. Қалғандары (26/29/35/43 мм — қалың МДФ фасад, столешница
  жиегі) әдейі тасталды: ол қажет болса, кейінгі импорт.
- **Кромка қалыңдығы 0.4/1/2 мм.** `types.ts:67` комментарийіндегі жобаның
  өз конвенциясы («0.4 | 1 | 2 мм»). Базада 0.8 мм де бар (ABS таспа, 274
  жол осы ен ішінде) — ол ЕШҚАШАН қолданылмайды деп айтылмаған, тек қазіргі
  конвенциядан тыс, сондықтан бірінші импортта тасталды.

## 2. МДФ толығымен алынып тасталды

Тапсырма МДФ-ты «мысалы» тізіміне қосқанымен, нақты тексеру көрсетті:
базада МДФ 16/18 мм — небәрі **8 жол**, әрі барлығында `Длина`/`Ширина`
бағаны 0, ал `Шаг по Х/Y` — **1000×1000** (fallback-маркер, нақты өлшем
емес, §4 `materials-db.md`-мен салыстыр). Яғни базада МДФ-тың **нақты
парақ өлшемі мүлде жоқ**.

`CLAUDE.md` §10: «ереже белгісіз болса — сұра, болжама». Ойдан 2800×2070
қою — дәл сол болжам болар еді. Сондықтан МДФ импортталмады; жоба бұрыннан
`seed.ts`-те екі МДФ позициясымен қамтылған (`mdf16-paint`, `mdf19-paint`,
қолмен енгізілген 2800×2070 өлшеммен) — олар қолданыстан қалады.

## 4. Парақ өлшемі — түзетілген қорытынды

`materials-db.md` §4 «Длина/Ширина парақ материалдарда әдетте 0» деп
жазған, БІРАҚ бұл толық датасеттің (барлық қалыңдық) статистикасы. Тек
16/18 мм ішінде тексергенде — **керісінше**:

| Өндіруші | `Длина`/`Ширина` | `Шаг X`/`Шаг Y` | Қолданылған |
|---|---|---|---|
| Lamarty, Увадрев | 2750 / 1830 (нақты) | 1830/2750 (сирек 1000×1000) | `Длина`/`Ширина` |
| Egger | 2800 / 2070 (нақты) | 1300/2800 (текстура қадамы, ПАРАҚ ЕМЕС) | `Длина`/`Ширина` |
| Стандарт | 0 / 0 | 2070/2800 | `Шаг X`/`Шаг Y` fallback |
| ХДФ (бәрі) | 0 / 0 | 2070/2800 | `Шаг X`/`Шаг Y` fallback |

Ереже (`importBasis.mjs` → `sheetDims()`): `Длина>0 && Ширина>0` болса — солар
парақ өлшемі; болмаса `max(ШагX,ШагY)` / `min(ШагX,ШагY)` fallback. Бұл
ереже Egger үшін өте маңызды: Egger-де `Шаг X/Y` (1300×2800) НАҚТЫ ПАРАҚ
ЕМЕС, декор текстурасының қайталану қадамы ғана — оны парақ өлшемі ретінде
алса, 1300 мм-лік «парақ» пайда болар еді (шындыққа жанаспайды, Egger
нарықта 2800×2070 сатады).

## 5. Баға — ШЕШІМ

**Барлық `pricePerSheet` / `pricePerMeter` — 0, БІР ерекшелікпен.**

Негіздеме (`CLAUDE.md` §0.2 — ақша бүтін тиын, ойдан жазуға болмайды):

1. Базистің `Стоимость` бағанының валютасы құжатта ЕШҚАНДАЙ жерде
   көрсетілмеген (§6, `materials-db.md`). 2023 жылғы орыс көтерме бағасына
   ұқсас (болжам — рубль), бірақ расталмаған.
2. Тіпті рубль болса да, теңгеге курспен аудару ҚАТЕ: курс 2023-тен бері
   өзгерді, әрі көтерме баға мен ҚР бөлшек/жеткізу бағасы бірдей емес.
3. Сондықтан бағаны **аудармау**, тек «белгісіз» деп белгілеу дұрыс шешім —
   0 баға `pricing.ts`-те (§7) қауіпсіз өңделеді, ал ойдан жазылған сан
   клиентке кеткен КП-ға түсіп кетуі мүмкін еді (`pricing.ts:83` комментарийі
   дәл осыны айтады).

**Бір ерекшелік: 457 Egger 2800×2070 ЛДСП жазбасы.** Оларға
`pricePerSheet = 3 400 000` тиын (34 000 ₸) қойылды — бұл
`docs/audit/qdesign-drilling-reference.md`-те (2026-09-20 сеансы,
пайдаланушы қосқан) qdesign.kz-тен оқылған НАҚТЫ ҚР бағасы, формат
2800×2070 сол құжатта тікелей аталған.

⚠ **Бұл баға ДЕКОРҒА БӨЛІНБЕГЕН** — qdesign-де де жалпы «Egger парағы»
деп оқылды, нақты декорға қарай (мыс. H1145 Дуб Бардолино мен U156
Бежевый песок) бағасы шын өмірде әртүрлі болуы мүмкін (Базистің өз
«Стоимость» бағанында да Egger диапазоны 420–14 400 аралығында — үлкен
айырма). Сондықтан бұл — **бастапқы нұсқа/бағдар**, цех әр декорды өзінің
нақты жеткізушісінен тексеріп, қажет болса түзетуі керек.

**Kronospan базада МҮЛДЕ ЖОҚ** (`materials-db.md` §2, тексерілді), сондықтан
оның 16 500 ₸ бағасы (qdesign-дегі) ешбір материалға ЖАЛҒАНБАЙДЫ — ойдан
Kronospan материалы қосу тыйым салынған («Құқықтық шекара» + `CLAUDE.md`
§10). Екі анықтамалық баға да скрипттің басында (`KZ_REFERENCE_PRICES`)
тұр, тек құжаттама/келешек үшін.

**Баға сенімділігінің белгісі.** `Material`/`EdgeBand` типінде (`types.ts`)
баға дереккөзі өрісі жоқ (бөгде агент иеленеді, өзгертілмеді). Сондықтан
бөлек файл: `src/core/data/basisPriceMeta.ts` → `BASIS_PRICE_META[id]`:

```ts
{ priceSource: 'unknown' | 'kz-quoted-generic', note: string }
```

`pricing.ts`-ке ТІКЕЛЕЙ кірмейді — тек құжаттама мен цехтың баға тексеруі
үшін. `pricing.ts` баға-нөлдік материалды `missingPrices` тізіміне жазады,
ЛАҚТЫРМАЙДЫ (`pricing.ts:302`, тексерілген тест — §7 төменде).

## 6. `hasGrain` эвристикасы және дәлдігі

Базада бұл өріс МҮЛДЕ ЖОҚ (`materials-db.md` §8). Екі деңгейлі эвристика:

1. **Egger — декор коды бойынша (ЖОҒАРЫ сенімді).** Egger-дің өз
   номенклатурасында декор коды префиксі мағына білдіреді: `H` = Holzdekor
   (ағаш), `U`/`W` = Uni/White (біртүсті). Бұл ӨНДІРУШІНІҢ конвенциясы,
   болжам емес. Тексеру: 457 Egger жолының атауындағы орысша сөзбен
   («дуб», «вишня», т.б., §-дегі WOOD_WORDS) кросс-валидацияланды —
   **447/457 = 97.8% сәйкес келді**. Қалған 10 алшақтық негізінен
   өнім атауы («Баменда», «Флитвуд», «Файнлайн») орысша сөздікте жоқ
   меншікті атаулар, декор коды дұрысырақ деп есептелді (H-код басым).
2. **Lamarty / Увадрев / Стандарт — тек түйінсөз іздеу (ТӨМЕН сенімді).**
   Код жоқ, тек атаудағы орысша сөз («дуб», «ясень», «орех», ...,
   `WOOD_WORDS` тізімі, 40 сөз). **Салыстыратын «дұрысы» жоқ** — сондықтан
   нақты дәлдік ӨЛШЕНБЕГЕН, тек Egger-мен ұқсастығына сеніп қолданылды.
   Бір НАҚТЫ жалған позитив табылды әрі түзетілді: «Дублин» (Увадрев
   декоры) «дуб»-тан басталады, бірақ қаланың атауы — ағашқа қатысы жоқ
   (`FALSE_POSITIVE_NAMES` тізіміне қосылды).

**⚠ Белгілі шектеу (JS-тің `\b` гочасы).** Бірінші нұсқада кирилл сөзге
`\bдуб\w*` қолданылды — JS-тің `\b`/`\w` ТЕК ASCII үшін жұмыс істейді,
кирилл әрпін «сөз таңбасы» санамайды, сондықтан кирилл мәтінде `\b` ЕШҚАШАН
сәйкес келмеді (бірінші өткізуде hasGrain=true тек Egger-де ғана шықты,
192/1767 — бұл дұрыс емес еді). Түзетілді: `(?<![қаріп])(сөз)[қаріп]*`
look-behind/ahead схемасымен. Түзетуден кейін: **578/1767 (32.7%)
hasGrain=true**, өндіруші бойынша: Egger 192/457 (42%, код бойынша),
Увадрев 170/426 (40%), Lamarty 112/522 (21%), Стандарт 104/180 (58%) —
таралуы кескінді материалдар нарығына жақын (ағаш пен түс декорының
шамамен тең қатынасы), бұл эвристиканың ЖАЛПЫ БАҒЫТЫ дұрыс екенін
көрсетеді, бірақ жеке-жеке 100% растау жоқ.

**Қолмен тексеру ұсынылады:** Lamarty/Увадрев/Стандарт декорларының
(1 128 жол) `hasGrain` мәні — БОЛЖАМ, тексерілмеген. Цех тапсырыс алдында
күмәнді декорды (шетінен қарап) растауы керек.

## 7. Тесттер

`tests/basisImport.test.ts` (9 тест, барлығы өтеді):

- `BASIS_MATERIALS`/`BASIS_EDGE_BANDS` бос емес, id бәрі бірегей
  (материал + кромка бірге, 3 613 жазба)
- Қалыңдық пен парақ өлшемі бәрінде > 0
- Импортталған қалыңдық жиынтығы дәл `{3, 4, 16, 18}` (ЛДСП/ХДФ) және
  кромкада `{0.4, 1, 2}` — сүзгінің дәл сақталғанын растайды
- Баға шешімі: тек Egger 2800×2070-де баға бар әрі `priceSource` дәл
  сол материалдарда `'kz-quoted-generic'`, қалғанында `'unknown'`
- `hasGrain` екі мәні де бар (тек true/тек false емес — эвристика жұмыс
  істейтінін растайды)
- `generateCabinet` Базис материалымен НАҚТЫ шкаф жинайды (ЛДСП 16 + ХДФ 3,
  2000×600×450, 4 сөре, 2 фасад) — барлық панельдің `materialId` каталогта
  бар
- `priceProject` бағасы 0 материалмен ЛАҚТЫРМАЙДЫ, оның орнына
  `missingPrices` тізіміне материал атауын жазады (нақты `nestPanels()`
  раскроймен тексерілді — бос/жалған раскроймен `sheets=0` болып, тексеріс
  іске қоспай өтіп кетуші еді, бұл қате бастапқы нұсқада ұсталды)

`npm test` толық жобамен: **93 файл, 1203 тест — БӘРІ өтеді** (бұл
тапсырма кезінде, 2026-09-20). Басқа үш агенттің файлдарына тәуелділік
жоқ — жаңа файлдар ғана, `seed.ts` тиілмеді.

Базада `Цвет (HEX)` бағаны бар (322 бірегей мән — толық датасетте), бірақ
**біздің сүзілген 16/18 мм ЛДСП ішінде тек 2 мән кездеседі: `#FFFFFF` және
`#00FF00`** (соңғысы — Base3D-тің әдеттегі «текстура жоқ» хром-кілт түсі).
ХДФ-та да тек 2 мән, кромкада 3. Яғни бұл баған біздің қима бойынша
**толтырылмаған, плейсхолдер** — нақты декор түсін бермейді.

Ойдан «жуық» түс жазу орнына (қате ақпарат), `decor` өрісі мүлде
қалдырылды. `types.ts:33-36` комментарийі дәл осы жағдайды жобалаған:
«Болмаса, көрініс бейтарап сұр түспен салынады» — жоба өзі көздеген
үнсіз тәртіп қолданылды.

## ✅ Түзетілді — 1000×1000 fallback (2026-09-20)

**Ақау табылды:** импортталған 1 767 материалдың **екеуінде** парақ өлшемі
`1000×1000` — ол нағыз өлшем емес.

```
«ХДФ 04мм»   t=4   1000×1000   баға 0   ← fallback ақауы
«ХДФ 03мм»   t=3   1000×1000   баға 0   ← fallback ақауы
```

**Себебі:** дереккөзде сол екі жолда `Длина`/`Ширина` = 0, ал `Шаг X/Y`
(текстураның қайталану қадамы) = 1000/1000 — Базистің өз толтырылмаған
жазбасы. Импорттаушының fallback ережесі (`Шаг`-тан алу) өткізіп жіберді.

**Түзету орындалды:**

Скрипт `scripts/importBasis.mjs`-ке ереже қосылды: fallback-та парақ өлшемі
(stepX/stepY-дан) < 1500 болса, жазбаны **тастап кету**. Ережелер:

1. Егер `Длина`/`Ширина` > 0 — пайдаланамыз (нақты өлшем).
2. Әйтпесе, `Шаг X/Y` > 0 болса — fallback (`Math.max/min`).
3. **ЖАҢА:** fallback өлшемі < 1500 болса — жазбаны өткез (тастау).
4. Екеуі де жарамсыз болса — өткез.

Бұл МДФ-ті тастау шешімімен (§«Не алынбады») бірдей логика.

**Нәтиже:**

|---|---:|---:|---|

| ХДФ | 182 | 180 | −2 |
