# Базис-Мебельщикке скрипт экспорты (панель + присадка)

> 2026-09-24. Код: `src/core/export/basisScript.ts` (деректер), `basisScriptBody.ts`
> (Базисте орындалатын JS), `basisAudit.ts` (қайтқан audit-ты талдау),
> `basisTestKit.ts` (тест-жинақ). CLI: `npm run bazis:kit`, `npm run bazis:audit`.
> Тесттер: `tests/basisScript.test.ts`, `tests/basisAudit.test.ts`,
> `tests/basisTestKit.test.ts`, `tests/basis.test.ts`.

## 1. Неге скрипт

- Базис-Раскрой тек **детальдер тізімін** Excel-ден оқиды; Базис-Мебельщиктің импорт
  форматтарында присадка **жоқ** (`.codex-runs/basis-drilling-import-route.md`).
- Присадканы Базиске жеткізудің жалғыз құжатталған жолы — Базистің ресми JavaScript API-і
  (https://github.com/BazisSoft/Scripts, MIT). Базисте тесік жеке нысан емес: ол **крепеж
  моделінен** шығады. Сондықтан скрипт тесікті емес, **крепежді** қояды:
  `Mount(panel1, panel2, x, y, z)` (екі деталь арасына) не `Mount1(panel, x, y, z, angle)`
  (бір детальдің бетіне).
- Сол себепті «Базис» бумасынан `prisadka.csv` **алынды**: оны ешбір Базис модулі оқымайды.
  Станокқа присадка — «ЧПУ по деталям» экспорты арқылы.

## 2. Қалай жұмыс істейді

1. `basisScriptData(scene, catalog, settings)` — `flattenTree` (не UI-дағы `useSceneItems`)
   нәтижесінен бір JSON блок жасайды:
   - **панельдер**: ГОТОВЫЙ өлшем (рез емес — `basis.ts`-тегі ереже), қалыңдық, материал
     атауы мен id-і, әр жақтың кромкасы, Базис әлеміндегі габарит (min/max), нормаль осі,
     текстура осі;
   - **крепеж**: түрі, `pair`/`single`, қай панельдер, орнату нүктесі мен осі, және оған
     тиесілі `drilling.ts` тесіктерінің бәрі (әлем координатасымен). **Әр тесік дәл бір
     крепежде** — тестпен тексерілген.
2. Тесіктерді крепежге топтау (`groupHoles`), бүкіл сахна бойынша:
   - конфирмат, минификс, шкант, ящик фасадының еврошурупы — осьтері бір түзуде не
     қиылысатын тесіктер бір буын (60 мм радиус). 1-деталь — бұранда **торцына** кіретін
     деталь (ресми Aventos HF мысалындағы `Евровинт.Value.Mount(Полка, Бок, …)` реті);
   - ілгек — әр чашка бір крепеж, бекіту мен планка тесіктері ең жақын чашкаға;
   - тұтқа — бір фасадқа бір; направляющая — бір панельде бір биіктіктегі тесіктер;
   - аяқ — бір дноның төрт бұрандасы; полкодержатель — әр тесік бөлек.
3. Координата: біздің әлем (X оңға, Y жоғары, Z **артқа**) → Базис (X оңға, Y жоғары,
   Z **алға**): `Z_б = zShift − z`. Бұл айна емес, тек бағыт ауыстыру. Дәлел: Aventos HF
   мысалында арт қабырға z≈16-да, есік `z = Depth`-те, тұтқа `Depth + Thickness`-те.
4. Скрипт (`basisScriptBody.ts`, ES5): қасиеттер панелінде крепеж/кромка таңдауы →
   панельдерді түйін-блоктармен (`BeginBlock`) құрады → крепеж қояды → есеп (`alert`) →
   **AUDIT** (5-бөлім).
5. Файл UTF-8 + BOM (ресми «Замена материала.js» солай). Код жолдарында тек ASCII:
   кириллица `\uXXXX` болып жазылған, сондықтан ескі Базис файлды CP1251 деп оқыса да,
   тек комментарий бұзылады.

## 3. Цехке: орнату және бірінші іске қосу

1. Конфигуратордағы «Раскрой» бетінде **«Базис»** батырмасы → zip. Ішінде:
   `detali.csv`, `detali.xlsx` (Базис-Раскройға, «Длину и ширину считывать как готовую»),
   `bazis-import.js`, `README.txt`, `dxf/`.
2. `bazis-import.js`-ті Базистің **Scripts** қалтасына көшіріңіз, Базис-Мебельщикте
   жаңа модель ашып, скриптті іске қосыңыз.
3. **Бірінші рет** оң жақтағы «Свойства» панелінде біздің әр крепеж түріне
   (конфирмат, минификс, шкант, ілгек, полкодержатель, тұтқа, направляющая, аяқ,
   ящик фасадының еврошурупы) Базис базасынан крепежді, әр кромкаға кромка материалын
   таңдап, **«Построить»** басыңыз. Таңдау скрипттің жанындағы
   `furniture-configurator-basis.xml` файлына сақталады (`Prop.Save/Load`).
4. Келесі жолы бәрі таңдалған болса, скрипт бірден құрады. Қайта таңдау керек болса —
   «Всегда показывать сопоставление» құсбелгісін қойыңыз не XML-ді өшіріңіз.
5. Крепеж таңдалмаған түрдің тесіктері **болжанбайды**: соңғы хабарламада түрі, тесік
   саны мен детальдері жазылады.

## 5. AUDIT: скрипт өзін тексереді

Құрғаннан кейін скрипт Базистен қайта оқиды және ішіндегі күтілген деректермен
салыстырады (шек ±0.5 мм). Әр қадам `try/catch`-та: бір қате бүкіл audit-ты тоқтатпайды,
`errors` тізіміне жазылады.

- **Панель**: аты, UID, материал, қалыңдық, контур өлшемі (`ContourWidth/Height`),
  `GSize`, габарит (`GabMin/GabMax`), орны, нормаль (`NToGlobal(AxisZ)`), текстура,
  кромкалар (`Butts`: элемент, біздің жақ, материал, қалыңдық, `ClipPanel`), біздің
  тесіктердің панель-локал координатасы (`ToObject`) және панельдің барлық қарапайым
  қасиеттері (рефлексия — Базистің шын API-ін білу үшін).
- **Крепеж**: аты, UID, орны, габарит, бағыты, біріктірген панельдері
  (`FindFastenedObjects`).
- **Тесіктер** (бар болса): жаңа API `fastenerOperations.NewHoleDrilling()` → әр панельдің
  тесіктері (диаметр, тереңдік, крепеж аты) және тесік объектісінің барлық қасиеті.
  Тесіктің **орны** мысалда құжатталмаған, сондықтан салыстырушы тесіктің кез келген
  вектор өрісін біздің нүктемен **әлемде** де, **панель-локалда** да салыстырады да,
  қайсысы сәйкес келгенін жазады (`world:Position` т.с.с.) — осылай Базистің келісімін
  тестерден білеміз.
- **Орта**: `system.apiVersion`, `developerApiVersion`, `apiVersion.GetScriptApiVersion()`,
  негізгі глобалдардың `typeof`-ы, модель файлы, уақыты; тестер таңдаған крепеж.
- Файлдар: `<жоба>-bazis-audit.json` (толық) және `.txt` (қысқа, орысша). Орны:
  1) сақталған модельдің қалтасы (`Action.ModelFilename`); 2) болмаса — тестер өзі
  таңдайды (`system.askFileNameSave`); 3) болмаса — скрипттің қалтасы. Соңғы хабарлама
  файлдың орнын және «отправьте этот файл» дейді.

Біз жақта: `npm run bazis:audit -- <файл>.json [--out bazis-audit-report.md]` —
салыстыруды шикі деректерден **қайта** жасайды (скрипттің өз есебін тек айқастырады) және
қазақша есеп жазады: мәселе түрі бойынша топталған (өлшем, орын, нормаль, кромка,
ClipPanel, крепеж орны/панельдері, тесіктің жоқ/артық/диаметр/тереңдік/орны), әрқайсысына
ықтимал себеп (осьтер келісімі, готовый ↔ рез, крепеж моделінің айырмасы). Кей жағдайда
себепті өзі табады: Z айнасы, қалыңдық теріс жаққа өсуі, кромкаға тең кішірею.

**Тест-жинақ** (`npm run bazis:kit` → `dist/bazis-test-kit.js`): бір жобада бәрі бар —
төменгі корпус (конфирмат, полкодержатель, аяқ, сыртқы беттегі тұтқа, press-fit чашка),
ящикті тумба (направляющая, минификс Ø5, ящик түбінің шканты, еврошуруп), футоркалы
минификс (Ø8), бұрандалы чашкалы аспалы шкаф, көтерілетін фасад, бұрыштық корпус, пазды
арт, жақтары әртүрлі кромкалы тақта + қолмен шкант, 90°-қа бұрылған кірістірілген топ.
⚠ Ондағы press-fit 12 мм, pilot Ø2.8×8, футорка 12 мм — `tests/shopDrilling.test.ts`-тің
**тест мәндері**, өндіріске емес.

Дәлел: **manual** — «Работа со скриптами», Руководство пользователя (Script.pdf, 2021);
**example** — ресми мысал (GitHub BazisSoft/Scripts не BAZIS-Script_examples.html);
**types** — тек `@types/bazis/index.d.ts` (мысалсыз). Бәрі `basisScriptBody.ts`-тің
`adapter*` функцияларында.

Скрипттің әр API атауы `bazis.d.ts`-те не жоғарыдағы «тек example» тізімінде
(`BASIS_API_FROM_EXAMPLES`) бар екенін тест тексереді (`tests/fixtures/bazis/`, MIT).

⚠ Жаңа Базисте классикалық глобалдар (`AddVertPanel`, `Action`) әдепкіде бар-жоғы
белгісіз: мысалдар беті «Версия API» бөлімінде ескі функционал `apiVersion`
төмендегенде ғана жүктелетінін айтады. Audit-тың `environment.globals` өрісі соны көрсетеді.

## 7. Базиссіз ТЕКСЕРІЛМЕГЕН (шын Базисте тексеру керек)

1. Скрипт шын Базисте қатесіз жүре ме (классикалық API қолжетімді ме — `environment`).
2. Панельдердің габариті мен нормалі (A1), Z бағыты — `panel-position`, `panel-normal`.
3. Кромка дұрыс торцқа түсе ме (A3) және `ClipPanel` сақтала ма (A4) — Базистің рез
   өлшемі біздікімен бірдей ме.
4. Крепеждің нүктесі мен панельдер реті (A5) — `fastener-point`, `fastener-panels`;
   тұтқаның бұрышы.
5. Базистің крепеж моделі бұрғылаған тесіктер біздікімен бірдей ме (диаметр, тереңдік,
   орны, беті) — `hole-*`.
6. Сәйкестендіру XML-і келесі іске қосуда оқыла ма.
7. Audit файлы жазыла ма және қай жерге.

Мұның бәрін **бір** audit файлы көрсетеді — тест-жинақты бір рет іске қосу жеткілікті.

## 8. Табылған ескерту (осы жұмыс барысында)

Көп секциялы шаблондарда (`wardrobe-2sec-1200`, `wardrobe-3sec-1800`, `bookcase-2sec-1200`,
`kitchen-wall-open-800`, `tv-stand-1200`, `chest-wide-1200`, `wardrobe-drawers-1200`,
`wardrobe-sliding-3-2400`) перегородкада **бір бетте, бір координатада қайталанған**
полкодержатель тесіктері бар (мыс. `divider-1` inner x=256 y=35 екі рет). Бұл ілгек
планкасындағы §R4 мәселесіне ұқсайды (екі секция бір бетке жазады). Скрипт оларды екі
бөлек крепеж етіп береді; `drilling.ts`-ті тексеру керек — бұл жұмыста түзетілмеді.

## Инструкция для тестировщика (с Базисом) — 1 страница

**Что это.** Файл `bazis-test-kit.js` — скрипт для Базис-Мебельщика. Он сам строит
тестовый набор мебели, ставит крепёж, проверяет результат и пишет **один файл сверки**.
Скриншоты не нужны — пришлите только этот файл.

1. **Скопируйте** `bazis-test-kit.js` в папку **Scripts** Базиса.
2. Откройте Базис-Мебельщик, создайте **новую модель** и **сохраните** её в любую папку
   (тогда файл сверки появится рядом с моделью).
3. **Запустите** скрипт `bazis-test-kit.js` (меню скриптов).
4. Первый запуск: справа в панели «Свойства» **один раз выберите**:
   - для каждого нашего типа крепежа — крепёж из вашей базы Базиса
     (конфирмат, минификс, шкант, петля, полкодержатель, ручка, направляющая, опора,
     евровинт фасада ящика). Если подходящего нет — оставьте пустым: эти отверстия
     просто не будут переданы и попадут в отчёт;
   - для каждой нашей кромки — кромочный материал близкой толщины;
   - нажмите **«Построить»**.
5. Дождитесь сообщения «Импорт из конфигуратора — итог». В конце сообщения указано,
   **где лежит файл** `bazis-test-kit-bazis-audit.json` (и `.txt`).
