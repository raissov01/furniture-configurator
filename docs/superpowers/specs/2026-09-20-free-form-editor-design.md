# Еркін редактор өзегі — дизайн

**Күні:** 2026-09-20
**Бұтақ:** `feat/tree-core`
**Күйі:** мақұлдауға дайын

---

## 1. Не үшін

Жобаның мақсаты — PRO100 (Ecru Software, поляк жиһаз жобалау бағдарламасы)
деңгейіндегі, бірақ қазақстандық нарыққа бейімделген веб-конфигуратор.

PRO100 v7.08 талданды (`PRO100.rus` ресурс DLL-інен 592 интерфейс жолы мен
60 диалог терезесі, `PRO100.ini`-ден кітапхана құрылымы, `textures.ini`-ден
материал моделі). Талдау нәтижесі: **өндірістік тізбектің бәрі бізде бар**
(деталировка, раскрой, присадка, смета, DXF, ЧПУ, этикетка), ал PRO100-дан
ең үлкен айырмашылық — **редактор парадигмасы**.

| | PRO100 | Бізде қазір |
|---|---|---|
| Негізгі нысан | элемент = қорап, кез келген жерде | параметрлік корпус (`CabinetConfig`) |
| Ұя салу | элементтің ішіне элемент | жоқ |
| Топтау | «сборка», кітапханаға сақталады | жоқ |
| Еркін деталь | кез келген қорап | тек `CustomPart` (шектеулі) |
| Параметрлік корпус | **жоқ** | бар, күшті |

Шебер «мен қалағанымды құрастыра алмаймын» дегенді осы жерде айтады. Бұл
спек соны жабады.

## 2. Негізгі тұжырым

Қолданыстағы кодтың құрылымы мынандай:

```
CabinetConfig ──generateCabinet()──▶ Panel[] ──▶ cutList · pricing · nesting
                                                   · cutPlan · dxf · cnc
                                                   · labels · quotePdf
Placement ─────────────────────────▶ 3D-дегі орны
```

**Бүкіл өндірістік тізбек бір ғана нәрсені тұтынады — `Panel[]`.** Ал
`Panel`-да `position: Vec3` (AABB-тың мин бұрышы) мен `rotation: Vec3`
(градус) бұрыннан бар, яғни панельдің өзі де бағытталған қорап.

Демек еркін редактордың өзегі `Panel[]` шығарса болғаны — сонда **1083
юнит-тест, 21 e2e тест, раскрой, смета, присадка, DXF өзгеріссіз жұмыс
істейді.** Дизайн толығымен осы тұжырымға сүйенеді.

## 3. Қарастырылған тәсілдер

**A. Бірыңғай ағаш, генератор — сол ағаштың бір түйіні. ✅ ТАҢДАЛДЫ**
Жобаның өзегі — түйіндер ағашы. Түйін не еркін тақта, не параметрлік корпус,
не топ. Бәрі бір `flattenTree()` арқылы `Panel[]`-ге жайылады.
*Плюс:* PRO100 парадигмасы толық шығады, генератор жоғалмайды, екеуі бірге
PRO100-нан күштірек болады. *Минус:* `ProjectFile` v3 → v4 миграциясы.

**B. Еркін тақталар — `cabinets` қасындағы бөлек тізім.** ❌
Қазіргі `CustomPart`-ты өсіру. Тез бітеді, бірақ ұя салу да, топтау да жоқ.
PRO100-дың UX-і «элементтің ішіне элемент салу» үстінде тұрғандықтан парити
шықпайды.

**C. Генераторды алып тастап, бәрін қорапқа айналдыру.** ❌
Присадка қозғалтқышы қай панель «бет», қай панель «жиек» екенін генератордың
ішінде біледі (`confirmatJoint`, `minifixJoint`). Қорапқа айналдырсақ сол
білім жоғалады, параметрлік қайта өңдеу де кетеді.

## 4. Өзек: түйіндер ағашы

Жаңа файл `src/core/tree.ts` — таза TypeScript, three.js/React импорты жоқ
(жобаның қолданыстағы ережесі).

```ts
/** Ата-түйінге ҚАТЫСТЫ орны. мм бүтін, градус. */
export type Transform = { pos: Vec3; rot: Vec3 }

export type SceneNode = GroupNode | CabinetNode | BoardNode | SolidNode

type Base = {
  id: string
  name: string
  transform: Transform
  hidden?: boolean | undefined
  locked?: boolean | undefined
}

export type GroupNode   = Base & { kind: 'group';   children: SceneNode[] }
export type CabinetNode = Base & { kind: 'cabinet'; config: CabinetConfig }
export type BoardNode   = Base & { kind: 'board';   board: BoardSpec }
export type SolidNode   = Base & { kind: 'solid';   solid: SolidSpec }

/** Еркін тақта = бір деталь. Panel-ге тура айналады. */
export type BoardSpec = {
  materialId: string
  /** ГОТОВЫЙ өлшем — рез өлшемі кромкадан есептеледі, қолмен енгізілмейді */
  length: number
  width: number
  orientation: Orientation
  edges: PanelEdges
  grainAlongLength: boolean
  role: PanelRole
  drilling?: Drill[] | undefined
  cutouts?: Cutout[] | undefined
  corners?: PanelCorners | undefined
  milling?: MillingPath[] | undefined
}

/** Өндіріске КЕТПЕЙТІН қорап: техника, тас, декор. */
export type SolidSpec = {
  size: Vec3
  color?: string | undefined
  textureId?: string | undefined
}
```

### Шешімдердің негіздемесі

- **`Transform` ата-түйінге қатысты.** Топты жылжытқанда балалары бірге
  жылжуы керек — PRO100-дағы мінез.
- **`CabinetNode` ағаштың ішінде.** Параметрлік шкафты топқа салып, «ас
  үйдің төменгі қатары» деген сборка жасап, кітапханаға сақтауға болады.
  PRO100-да бұл мүмкін емес: онда бәрі өлі қорап.
- **`SolidNode` бөлек тип.** Техника мен декор деталировкаға түспеуі керек.
  Шекараны типтің өзі ұстайды — есеп жазатын кодта `if` керек емес.
- **`BoardSpec`-те `cutLength`/`cutWidth` жоқ.** Рез өлшемі кромка
  қалыңдығынан есептеледі (`edges.ts`). Оны қолмен енгізуге рұқсат етсек,
  екі ақиқат көзі пайда болады да, цехқа қате сан кетеді.

## 5. Жайылу (flatten)

Жаңа файл `src/core/flatten.ts`:

```ts
export type PlacedSolid = { nodeId: string; spec: SolidSpec; pos: Vec3; rot: Vec3 }

export function flattenTree(
  root: GroupNode,
  catalog: Catalog,
  settings?: SettingsOverride,
): { panels: Panel[]; solids: PlacedSolid[] }
```

Бір рекурсия, төрт тармақ:

| Түйін | Не істейді |
|---|---|
| `group` | балаларына түседі, әлем трансформасын **құрама** етеді |
| `cabinet` | `generateCabinet(config, catalog, settings)` шақырады, қайтқан панельдерге әлем трансформасын жағады |
| `board` | бір `Panel` жасайды; `cutLength`/`cutWidth` — `edges.ts` ережесімен |
| `solid` | `panels`-ке ЕШТЕҢЕ қоспайды, тек `solids`-ке |

`hidden: true` түйін **екеуіне де қосылмайды** — көрінбейтін деталь
деталировкаға да, сметаға да түспеуі керек (әйтпесе клиент көрмеген нәрсеге
ақша төлейді).

Шыққан `Panel[]` — әлем координатында. Одан кейінгі кодтың бірі де
өзгермейді: `formatCutList`, `groupPanels`, `pricing`, `nesting`, `cutPlan`,
`dxf`, `cnc`, `labels`, `quotePdf`, `hardwareList`, `basis`.

## 6. Миграция v3 → v4

`ProjectFile.schemaVersion` 3 → 4. `schema.ts`-те таза функция:

```
cabinets: CabinetConfig[] + placements: Placement[]  ──▶  root: GroupNode
```

Әр `CabinetConfig` → `CabinetNode`. `Placement`-тің `wall` + `offset` +
`elevation` + `rotate` қабырға геометриясы арқылы (`room.ts`-тегі бар
есеппен) `transform`-ға айналады. v4-те `placements` өрісі жоқ.

Ескі жобалардың бәрі ашылады. Бұл талап тестпен бекітіледі: репода бар
үлгі жобалар мен `SEED_SETS`/`SEED_TEMPLATES` арқылы.

## 7. Привязка, дәл енгізу, массив

Жаңа файл `src/core/snap.ts` — таза TypeScript.

```ts
export type SnapHint = {
  axis: Axis
  kind: 'face' | 'edge' | 'centre' | 'grid' | 'wall'
  at: number
  targetId?: string | undefined
}

export function snapPosition(
  moving: { pos: Vec3; size: Vec3 },
  others: { id: string; pos: Vec3; size: Vec3 }[],
  room: Room,
  opts: { grid: number; tolerance: number },
): { pos: Vec3; hints: SnapHint[] }
```

Үміткерлер әр өс бойынша бөлек жиналады, `tolerance` ішіндегі ең жақыны
алынады:

| Түрі | Не береді |
|---|---|
| `face` | көрші қораптың бетіне тіреу — ең жиі қолданылатыны |
| `edge` | жиектерін туралау (екі шкафтың алды бір сызықта) |
| `centre` | ортасын туралау |
| `wall` | қабырға, еден, төбе |
| `grid` | тор қадамы (әдепкі 10 мм, бапталады) |

Бетке тіреу материал қалыңдығын өзінен-өзі біледі, себебі `Panel.position`
бүтін миллиметр.

**Дәл енгізу.** Қасиеттер панелінде X / Y / Z және бұрылыс өрістері —
қазіргі сан өрісінің үлгісімен (`‹ ›` батырмалары). Тінтуірмен қою —
жуықтау, өріс — ақиқат.

**Массив:**

```ts
export function arrayNodes(
  node: SceneNode,
  opts: { axis: Axis; count: number; step: number },
): SceneNode[]
```

Таза функция, жаңа `id` береді, атына реттік нөмір қосады.

**Undo ережесі.** Бір қимыл — бір қайтару. Сүйреу кезіндегі аралық күйлер
тарихқа жазылмайды, тек `pointerup`-та бір жазба (55b8169-де орнатылған).

## 8. Интерфейс

### Құрылым ағашы

`components/ModuleList.tsx` (76 жол, жалпақ тізім) → `StructureTree`.
Қосылатыны: ұя (жиналады/ашылады), сүйреп ата-түйінді ауыстыру (топқа тастау
= PRO100-дың «вставить внутрь»-і), көз (`hidden`) және құлып (`locked`)
белгілері, көп таңдау (Shift/Ctrl), топтау `Ctrl+G`, тарату `Ctrl+Shift+G`.

> ⚠ **Гоча.** Жиналған тарау мазмұнын DOM-нан алып тастауға БОЛМАЙДЫ — e2e
> соқыр қалады әрі беттен іздеу жұмыс істемейді. Жасыру тек **класс
> арқылы**: Tailwind-тың `[hidden]` ережесі `:where()` ішінде (салмағы 0),
> ал `flex` утилитасы одан ауыр, сондықтан `hidden` атрибуты жұмыс істемейді.
> Бұл `components/ui.tsx`-тегі `Collapsible`-де шешілген, ағаш соны қолданады.

### Қасиеттер панелі

Орны — қазіргі оң жақ панель. Мазмұны түйін түріне қарай ауысады:

| Түйін | Не көрсетіледі |
|---|---|
| `board` | материал, ұзындық/ен, 4 жиектің кромкасы, рөлі, текстура бағыты, X/Y/Z, бұрылыс |
| `cabinet` | қазіргі толық панель (секциялар, фасад, ящик, аяқ) + X/Y/Z |
| `group` | аты, X/Y/Z, бұрылыс, балалар саны |
| `solid` | аты, өлшемі, түсі/текстурасы, X/Y/Z |

### 3D-дегі әрекет

Қазір таңдалған корпус қабырға бойымен сүйреледі (56f4758, жазықтығы
55b8169). Енді сүйрелетін нысан — кез келген түйін, ал жазықтық орнына
`snapPosition` жүреді. Қосылатыны: бұрылыс тұтқасы (90° қадам, `Shift` —
еркін), сүйреу кезінде привязка сызықтары, `Alt`+сүйреу = көшірме.

### Құралдар қатары

«Тақта қос», «Қорап қос», «Топ жаса», «Массив», «Көшір / Қой»,
«Қасиетін көшір / Қасиетін қой». Соңғы екеуі PRO100-да бар
(`Copy properties` / `Paste properties`), шеберлер жиі қолданады.

## 9. Кітапхана

PRO100-дың `.meb`-і — бір элемент немесе сборка. Бізде оның баламасы —
ағаштың бір бұтағы. Жаңа файл `src/core/library.ts`:

```ts
export type LibraryItem = {
  schemaVersion: 1
  id: string
  name: string
  /** Қалта = категория, PRO100-дағыдай */
  category: string
  node: SceneNode
  /** Қолданылған материалдар — жоба базасында жоқ болса */
  materials: Material[]
  thumbnail?: string | undefined
  meta: { author?: string | undefined; createdAt: string; sizeHint: Vec3 }
}
```

Қарапайым JSON: диффі көрінеді, git-ке түседі, тестке оңай. Бинарлық формат
жасалмайды.

**Екі деңгей:**

| Деңгей | Орны | Кім көреді |
|---|---|---|
| Тұқым (seed) кітапхана | репода JSON | бәрі |
| Шебердің өз кітапханасы | серверде, аккаунтқа байланған | тек иесі |

Аккаунт қабаты бар (`components/AccountPanel.tsx`, `lib/server/store.ts`),
соған қосылады.

**Қалта құрылымы** — PRO100-дың `PRO100.ini`-інен алынған:

```
кітапхана/  жиһаз/  элементтер/  материалдар/
шаблондар/  жобалар/  формалар/  материалдар/
прайс/
```

## 10. PRO100 номенклатурасын импорттау

Архивте 5 094 `.meb` бар. Олардың **атауларынан** шкаф типтерінің жүйесі
оқылады: `Н В3 500` = төменгі, 3 ящик, 500 мм; `В 2дв 800` = үстіңгі, 2
есік, 800 мм; `Н 2дв Мойка 900` = мойка астындағы.

```
npm run import:nomenclature -- --from <архив жолы>
```

Шығатыны — `CabinetTemplate[]` (тип бар, `templates.ts`-те 60-тан астам үлгі
жазылған). Пішінін біздің генератор шығарады, сондықтан кез келген өлшемге
бейімделеді.

**Көшірілмейтіні:** `.meb` файлдарының өзі (3D модельдер) және
`Библиотека/Материалы` ішіндегі 18 920 текстура суреті — олар үшінші жақтың
(Ecru, Egger, Blum) меншігі. Талдау көрсеткендей ол кітапхана бәрібір
жарамсыз: 18 920 суреттің тек 1 985-інде (10%) декор коды бар, прайс мүлде
жоқ, өндіруші мен артикул жазылмаған. Текстуралар декор коды бойынша
өндірушінің ашық порталынан алынады.

## 12. Тестілеу стратегиясы

1-фаза — ашық жүрек операциясы, сондықтан ол **тек өзекте**, UI-ға тимей
жасалады. Басты кепіл:

> `flattenTree()` шығарған `Panel[]` ескі жолмен (`generateCabinet` +
> `Placement`) шыққан `Panel[]`-ге **бірдей** болуы керек.

Бұл `SEED_TEMPLATES` мен `SEED_SETS` арқылы тестпен бекітіледі. Бірдей болса
— қалған тізбектің (раскрой, смета, присадка, DXF) бұзылмайтынына кепілдік
бар.

Қалған фазалар TDD-мен: `snap.ts`, `arrayNodes`, `library.ts` — таза
функциялар, тесті бұрын жазылады.

e2e (21 тест) әр фазада жүргізіледі. Ескерту: дев-сервер қосулы тұруы керек,
әйтпесе 12 тест жалған құлайды.

## 13. Шекаралар (бұл спекке КІРМЕЙДІ)

- **Еркін тақтаға автоматты присадка.** Қазіргі присадка қозғалтқышы қай
  панель «бет», қай панель «жиек» екенін генератордың ішінде біледі. Еркін
  тақтаны басқа тақтаға тіресең, бағдарлама олардың қалай бекітілетінін өзі
  шеше алмайды. 1-фазада тесік `DrillEditor`-мен қолмен қойылады. Кейін
  `autoJoint.ts` бөлек спекпен жасалады. **PRO100-дың өзінде де бұл жоқ**,
  сондықтан парити бұзылмайды.
- **Еркін пішін (токарлық, иілген деталь).** PRO100-да `TEDITLATHEFORM` бар.
  Бөлек спек.
- **Рендер қозғалтқышы** (PRO100-да Kray плагині). Бізде `RenderPanel` бар,
  бұл спекке кірмейді.
- **Прайс пен қазақстандық материал базасы.** Бөлек жұмыс, бұл спектен
  тәуелсіз.

## 14. CLAUDE.md-пен үйлесімі

`CLAUDE.md` §1-де «Non-goals» тізімі бар:

> - Free-form / organic modelling. Everything is axis-aligned rectangular panels.
> - A general CAD editor. This is a configurator with constrained parameters.

Бұл тізімнің басында **«do not build these unless explicitly asked»** деп
тұр. Пайдаланушы 2026-09-20-да еркін редактор өзегін нақты сұрады, сондықтан
шарт орындалды. 1-фазада `CLAUDE.md` жаңартылады: осы екі жол алынып,
орнына еркін редактордың шекарасы жазылады.

Нақтылау: бұл дизайн **органикалық модельдеуді қоспайды**. Түйіннің бәрі —
тікбұрышты, өстерге тураланған қорап. `BoardNode`-тың шығаратыны — кәдімгі
`Panel`, §4.3-тің кромка шегеру ережесімен. Яғни «axis-aligned rectangular
panels» деген талап бұзылмайды, тек оларды қолмен қоюға рұқсат беріледі.

Басқа тұстарда дизайн `CLAUDE.md`-ге сәйкес:
