## Әр қадамның мәні

### 1. Жарықтың `target`-і

`directionalLight`-та `target` проп мүлде жоқ. Three.js оны әдепкі `(0,0,0)`-ге
бағыттайды, ал бөлме сол нүктеден бұрышта басталады. Нәтижесінде 2048×2048
көлеңке картасының жартысынан көбі бос ауаға (≈16×16 м frustum) жұмсалады.

Түзету: `target`-ті бөлменің ортасына қою, `shadow-camera` шекарасын бөлме
өлшеміне тарылту. Кадр жиілігіне әсері нөл.

### 2. Терезе/есік шолу режимінде

`Scene.tsx:797` — ойықтар тек `walk === true` болғанда салынады. Яғни шебер
жобаны жасап отырғанда бөлмесі тұйық қорап, ойықтар тек прогулкада көрінеді.

⚠ Тексеру керек: шолу режимінде қабырға жартылай мөлдір болуы мүмкін, сонда
терезенің көрнекілігі қалай шығады.

### 3. `Decor.finish`

Қазір **барлық** панель бір материалмен: `roughness 0.7, metalness 0`
(`PanelMesh.tsx:516-519`, `:561-570`). Мат ЛДСП да, жылтыр фасад та, тас
столешница да, эмаль де.

```ts
export type DecorFinish = 'matte' | 'satin' | 'gloss' | 'stone' | 'metal'
// Decor-ге: finish?: DecorFinish | undefined
// undefined → 'matte' (қазіргі мінез, ескі жоба өзгермейді)
```

Нақты сандар `material.md`-де. `meshStandardMaterial` → жылтыр мен тасқа
`meshPhysicalMaterial` (`clearcoat`), қалғаны бұрынғыдай.

⚠ `envMapIntensity` қосу керек — `Environment` сахнада бар
(`Scene.tsx:1200-1204`), бірақ ешбір материал оны оқымайды, сондықтан жылтыр
бет шағылыспайды.

⚠ Тонмаппингке ТИМЕ: `NeutralToneMapping` әдейі таңдалған (ACES емес), ЛДСП
ағарып кетпеуі үшін, кодта түсініктемесімен.

### 4. `Decor.mapUrl` + `mapSizeMm`

Қазір нағыз текстура ЖОҚ. Бар нәрсе — `lib/grainTexture.ts`-тегі бір
процедуралық canvas суреті, ол барлық `kind: 'wood'` декорға бірдей жағылады,
тек `decor.color` реңкі өзгереді. Egger H1145 мен Kronospan K001 экранда
ажыратылмайды.

```ts
// Decor-ге:
mapUrl?: string | undefined      // өндірушінің ашық порталынан
mapSizeMm?: { x: number; y: number } | undefined  // текстураның ФИЗИКАЛЫҚ өлшемі
```

`mapSizeMm` — PRO100-дың `xmm`/`ymm` ұғымы. Онсыз масштаб қате: қазір
`tex.repeat.set(2, 2)` қатып қалған, яғни 300 мм панельде де, 2800 мм
панельде де сурет екі рет қайталанады.

📌 Үлгі бар: `lib/floorTexture.ts` мұны дұрыс шешкен (`SPAN_MM` арқылы), тек
ол тәсіл декорға қолданылмаған. Соны қайталау жеткілікті.

⚠ Үшінші жақтың сурет файлдарын репоға көшірмейміз — декор коды бойынша
сыртқы сілтеме.

### 5. `grainAlongLength` 3D-де

Раскройда бұл жұмыс істейді (`hasGrain` панельді 90°-қа бұруға тыйым салады),
бірақ 3D одан бейхабар. Яғни клиентке көрсетілген сурет пен цехтың кесетіні
сәйкес келмеуі мүмкін.

Бұл — эстетика емес, **нақты ақау**. §3-тің «3D — панель моделінің салдары»
деген ережесін бұзады.

### 6. Телефонда сапа

`lib/appearance.ts:33-35` — әдепкі сапа құрылғыға қарамайды. Сақталған таңдау
жоқ болғанда `matchMedia('(pointer: coarse)')` бойынша `medium` беру.

### 7. Rim жарығы

Үш нүктелі схемада артқы/бөлектеу жарығы жоқ. Қосқанда контур фоннан
айырылады. `castShadow={false}`, сондықтан шығыны минималды. Қатар:
`ambient` 0.12→0.08, `hemisphere` 0.3→0.22.

### 8. Еден

`oak` мен `walnut` бір текстураны қолданады, тек түсі бөлек
(`lib/floorTexture.ts` кэш кілті тек `pattern` бойынша).

## ЖАСАЛМАЙТЫНЫ

Бұл — **жиһаз конфигураторы, интерьер дизайн бағдарламасы емес**. Бөлмені
әсірелесек, жиһаздың өзі көрінбей қалады, ал клиент соған қарап ақша төлейді.

- Толық интерьер, жиһаздан тыс заттар (диван, өсімдік, сурет)
- Фотореалистік пейзаж, тұсқағаз каталогы
- Күрделі жарық сценарийлері (күн уақыты, маусым)
- Көлеңке картасын 4096-ға шығару немесе `AccumulativeShadows` —
  жобаның `frameloop='demand'` архитектурасымен қайшы
- Кромканы жеке физикалық мешь ету — мешь саны 4× өседі, пайдасы аз
