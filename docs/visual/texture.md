# Текстура — зерттеу нәтижесі

> Тек зерттеу. Ешбір код өзгертілмеген. Дереккөз: `src/core/decors.ts`,
> `src/core/types.ts`, `components/PanelMesh.tsx`, `components/Scene.tsx`,
> `lib/grainTexture.ts`, `lib/floorTexture.ts`, `components/DecorPicker.tsx`.

## Қысқаша жауап

**Нағыз текстура ЖОҚ.** Бар нәрсе — бір ғана процедуралық (canvas-та
генерацияланған) «түйіршік» суреті, ол барлық «ағаш» декорға БІРДЕЙ
жабыстырылады, тек негізгі түс (`decor.color`) арқылы реңкі өзгереді.
Egger H1145 мен Kronospan K001 экранда бір текстурамен, әртүрлі бояумен
көрінеді. Масштаб мм-мен байланысты емес, текстура бағыты (`grainAlongLength`)
3D-де мүлде ескерілмейді.

## 1. Қазіргі күй

### 1.1 Дерек моделі — тек түс, кескін жоқ

`src/core/types.ts:56-60`:

```ts
export type Decor = {
  color: string
  kind: 'solid' | 'wood'
}
```

`Material.decor` осы типті алады (`types.ts:33-37`). Ешбір өрісте `map`,
`textureUrl`, физикалық өлшем (мм) жоқ. `src/core/decors.ts` — 500-ден астам
жазбадан тұратын кітапхана (`DECOR_LIBRARY`, 38-563 жолдар), әр жазбада тек
`{ id, name, brand, code, kind, color, hasGrain }` (`decors.ts:23-36`). `color`
атаудан ШАМАМЕН шығарылған (файлдың басындағы түсініктеме, `decors.ts:11-14`)
— яғни бастапқыдан-ақ нақты фото емес, болжамды түс екені жазылған.

Артикул (`code`, мыс. `W980`, `H1145`) БАР, бірақ ол тек мәтін — сурет
іздеу/жүктеу үшін ешбір жерде қолданылмайды (репода `code`-қа сілтейтін fetch,
CDN URL, кэш кестесі жоқ — тексерілді: `grep -rn "code" src/core/decors.ts`
+ жоба бойынша `mapUrl`/`textureUrl`/`decorTexture` іздеуі нөл нәтиже берді).

### 1.2 Жалғыз текстура — процедуралық, барлығына ортақ

`lib/grainTexture.ts` (толық файл, 68 жол): 512×512 canvas, ашық фон
(`#f4f2ee`) үстіне 220 көлденең «талшық» сызығы + шу салынады. Функция
**singleton** (`let cached: Texture | null`, 16-17 жолдар) — бір рет
жасалып, бүкіл қосымшада БІР текстура пайдаланылады. `repeat.set(2, 2)`
қатаң тұрақты (63-жол), панельдің өлшеміне тәуелсіз. `anisotropy = 4`
қатаң тұрақты (64-жол) — GPU мүмкіндігі тексерілмейді
(`renderer.capabilities.getMaxAnisotropy()` шақырылмайды).

`components/PanelMesh.tsx:342-346`:

```ts
const woodDecor = useMemo(
  () => catalog.materials.find((m) => m.id === panel.materialId)?.decor?.kind === 'wood',
  [catalog, panel.materialId],
)
const grain = woodDecor ? grainTexture() : null
```

Бұл — жалғыз шарт: декор `kind === 'wood'` болса, СОЛ БІР `grain` текстурасы
алынады. Артикул, бренд, атау мүлде қатыспайды. Осы `grain` объектісі екі
жерде `meshStandardMaterial`-ге `map` ретінде беріледі: `PanelMesh.tsx:517`
(қиғаш/пішінді панельдер) және `PanelMesh.tsx:563` (қарапайым қорап-панель).
Түс өзі бөлек `color` пропынан келеді (`PanelMesh.tsx:457`,
`shade(decorColor ?? NEUTRAL, ROLE_SHADE[...])`) — яғни рендер = «бір
текстура × декордың hex түсі». Нәтижесінде екі әртүрлі дуб декоры (мыс.
Kronospan K076 «Дуб Экспресив Песочный» пен Egger W980 «Белый платиновый»)
ТЕК түсімен ажыратылады, ал беттің өрнегі бірдей.

Салыстыру үшін: еден текстурасы (`lib/floorTexture.ts`) да процедуралық,
бірақ ол кемінде физикалық мм-мен байланысады —
`SPAN_MM = 1200` тұрақтысы (`floorTexture.ts:20`) арқылы
`tex.repeat.set(widthMm / SPAN_MM, depthMm / SPAN_MM)` (`floorTexture.ts:80`)
жасайды. Декор текстурасында дәл осындай логика ЖОҚ — бұл нақты олқылық,
себебі үлгі («мм-мен масштабтау») жобада бұрыннан бар, тек декорға
қолданылмаған.

### 1.3 Материал таңдағыш (swatch) та жалған

`components/DecorPicker.tsx:14-20`: ағаш декор үшін нақты текстура емес,
CSS `repeating-linear-gradient` жолағы салынады. Яғни пайдаланушы декорды
таңдағанда да, 3D-де көргенде де — екеуі де жалған, бірақ ЕКІ БАСҚА жалған
көрініс (градиент ≠ canvas-түйіршік), сәйкессіздік бар.

### 1.4 Масштаб (мм) ұғымы — жоқ

PRO100-дегі `xmm`/`ymm` сияқты өріс жоба типтерінде мүлде жоқ (`types.ts`
толық оқылды — `Decor`-да, `Material`-да текстураның физикалық өлшемі
берілмейді). `grainTexture()` де параметрсіз шақырылады — панельдің
`finishedLength`/`finishedWidth` рендерге беріледі, бірақ текстура
функциясына ЕШҚАШАН жеткізілмейді (`PanelMesh.tsx:346` — `grainTexture()`
аргументсіз). Демек парақтың 2800 мм-де неше рет қайталанатыны концептуалды
түрде ЖОҚ — тек «бетке 2×2 тайл» деген құрғақ сан бар.

### 1.5 Текстура бағыты (`grainAlongLength`) — 3D-де ЖОҚ

`Panel.grainAlongLength` (`types.ts:258`) және `CabinetConfig.panelGrain`
(`types.ts:720`) бар, бірақ олар ТЕК мына жерлерде оқылады:

- `src/core/cutList.ts:92` — деталировкадағы «Текстура» бағаны үшін мәтін
- `src/core/nesting.ts:150` — раскрой алгоритміне (панельді 90°-қа бұруға
  бола ма) тыйым үшін
- `src/core/cutAdvice.ts:35-44` — кесу кеңесі үшін

`components/PanelMesh.tsx` мен `components/Scene.tsx` файлдарында
`grainAlongLength`-ке сілтеме **нөл** (тексерілді: толық grep). `grain`
текстурасының UV/`rotation`-ы панельдің бағдарынан (`orientation`) немесе
`grainAlongLength`-тен ешқашан есептелмейді — ол әрдайым бірдей көлденең
жолақ болып, `BoxGeometry`-нің әдепкі UV-мен `repeat(2,2)` арқылы тек
созылады/тайлданады.

**Салдары:** цех бір панельді (мыс. `panelGrain: 'width'` арқылы) көлденең
қиса да, 3D әрдайым бір бағытта көрсетеді. Клиентке көрсетілген сурет пен
цехтың кесетін парағы визуалды түрде АЙЫРЫЛУЫ мүмкін — бұл нақ CLAUDE.md
§4.3-тегі «ең қымбат қателік» рухындағы тәуекел, тек текстура бағыты
бойынша.

### 1.6 UV / созылу ма, тиленде ме

`PanelMesh.tsx:511-519` (пішінді панель, `extrudeGeometry`) және
`PanelMesh.tsx:550-570` (қарапайым, `boxGeometry`): екеуінде де геометрия
Three.js-тің ӘДЕПКІ UV-ін алады (арнайы UV есептеу жоқ). `BoxGeometry`-де
әр бет 0–1 диапазонында бір рет «созылады», содан кейін текстураның
`repeat(2,2)` қасиеті сол бетті 2×2 тайлға бөледі — бірақ бет
пропорциясына (ұзын/қысқа жиек) қарамастан бірдей сан. Нәтиже: кіші панель
(мыс. 300×400 мм сөре) мен үлкен панель (2000×600 мм бүйір) БІРДЕЙ тайл
тығыздығымен көрінеді — физикалық емес, әрі бір-бірімен сәйкессіз.

### 1.7 Ажыратымдылық / өнімділік

- Неше текстура: **1** (жалғыз `grainTexture()` singleton, барлық ағаш
  декорға ортақ) + еден үшін бөлек 1-2 (`floorTexture.ts` кэші, `paint()`
  паттерн бойынша кэштелген). Демек өнімділік тұрғысынан ЕШҚАНДАЙ мәселе
  жоқ — керісінше, өте арзан, себебі декордың нақты фотосы мүлде жүктелмейді.
- Өлшемі: 512×512 canvas, JS-те генерацияланады (файл жоқ, желіден
  жүктелмейді).
- KTX2/basis: жоқ, керек те емес (әзірге кескін файлдары жоқ).
- `anisotropy`: қатаң `4` (`grainTexture.ts:63`), GPU максимумына
  бейімделмеген.
- Mipmap: `CanvasTexture`-дың THREE.js әдепкісі бойынша қосулы (кодта
  арнайы өшірілмеген/қосылмаған — `generateMipmaps` еш жерде жазылмаған,
  демек әдепкі `true`).
- **Түйін:** қазіргі жүйе «жылдам, бірақ жалған» — өнімділік мәселесі жоқ,
  сапа мәселесі бар.

### 1.8 Текстура қайдан келеді

Ешқайдан — толығымен процедуралық (canvas, JS-те генерацияланады, желі
де, репо да, CDN да қатыспайды). Өндірушінің (Egger/Kronospan/Kastamonu)
ашық порталынан алу мүлде жоқ: fetch, кэш кестесі, прокси route — ешбірі
табылмады.

## 2. Табылған кемшіліктер (клиент көзіне түсу ретімен)

1. **Барлық ағаш декор бір-бірінен ажыратылмайды.** Клиент Egger H1145
   мен Kronospan K001 арасында таңдау жасағанда, 3D-де екеуі де «сарғыш
   жолақты қорап» болып көрінеді — тек реңкі басқа. Бұл ең көп көрінетін
   және сатуға тікелей әсер ететін кемшілік: клиент нақты декордың қалай
   көрінетінін көрмейді, тек болжам көреді. (`PanelMesh.tsx:342-346`,
   `grainTexture.ts` толығымен)
2. **Текстура бағыты 3D-де көрінбейді (`grainAlongLength` елеусіз).**
   Раскрой мен 3D сәйкессіз болуы мүмкін — клиентке көрсетілген сурет пен
   цехтың кескен парағы басқаша шығады. Бұл сенімге нұқсан келтіретін
   класс қате: көрінген нәрсе жинақталған нәрседен өзгеше. (§1.5)
3. **Масштаб мм-мен байланысты емес.** `repeat(2,2)` қатаң сан —
   PRO100-дегі `xmm`/`ymm` ұғымы жоқ. Әртүрлі өлшемдегі панельдер бірдей
   тайл тығыздығымен көрінеді, ал нақты өмірде үлкен парақта текстура
   көбірек қайталанады. Дизайнерге/клиентке масштаб сезімі бұрмаланған
   болып көрінеді. (§1.4, §1.6)
4. **Swatch (таңдағыш) пен 3D екі басқа жалған көрініс береді.**
   `DecorPicker.tsx` CSS градиент, ал 3D — canvas-текстура. Пайдаланушы
   таңдағанда көргені мен 3D-де көретіні сәйкес келмейді. (§1.3)
5. **`anisotropy` мен mipmap GPU-ға бейімделмеген**, бірақ бұл әзірге
   көрінбейтін, аз әсерлі мәселе (текстура кіші, бір данадан).

## 3. Жоспар

Мақсат: декорды **артикул бойынша** өндірушінің ашық порталынан алынған
шын суретпен, дұрыс мм-масштабпен, дұрыс бағытпен көрсету — үшінші жақ
файлдарын репоға көшірместен.

### Қадам 0 (алдын ала ескерту, «болжам»)

Egger/Kronospan/Kastamonu порталдарынан суретті ДЭЛ АЛУ құқықтық/техникалық
мәселе: көбінде ресми «swatch API» жоқ, тек сайттың өз CDN-і бар (hotlink
қорғанысы, ToS шектеуі болуы мүмкін). Бұл — жоспардың ең белгісіз бөлігі,
кодтан бұрын тексеру керек (порталдың robots.txt/ToS, ресми дилер API бар
ма). Осы құжат осы тәуекелді шешпейді, тек белгілейді.

### Қадам 1 — Тип өзгерістері (тәуекел төмен, ~30 мин)

`src/core/types.ts`-тегі `Decor`-ды кеңейту:

```ts
export type Decor = {
  color: string
  kind: 'solid' | 'wood'
  /** Нағыз текстура суретінің URL-і. Болмаса — процедуралық fallback. */
  mapUrl?: string
  /**
   * Текстураның физикалық жабатын ауданы, мм (PRO100-дегі xmm/ymm аналогы).
   * Мыс. Egger суреттері әдетте 300×300 мм не 600×600 мм үлгі данасын
   * көрсетеді — портал бойынша нақтылау керек.
   */
  mapSizeMm?: { x: number; y: number }
}
```

Барлық өріс `?` — миграция керек емес, ескі жоба файлдары бұрынғыдай
жұмыс істейді (`mapUrl` жоқ болса — §1.2-дегі fallback қалады). `decors.ts`
ішіндегі `DecorEntry`-ге де сол екі өріс қосылады (кітапхана деңгейінде),
себебі `code`/`brand` дәл сол жерде тұр.

### Қадам 2 — Суретті алу/кэштеу (сервер жағы, ~3-4 сағ, тәуекел орташа)

Next.js API route (мыс. `app/api/decor-texture/[code]/route.ts`):
артикул бойынша өндіруші порталынан суретті серверде жүктеп, өз
кэшінде (файл жүйесі/blob/DB) сақтайды да, `mapUrl` ретінде ӨЗ URL-ін
қайтарады. Бұл екі себеппен маңызды:

- CORS: браузерден тікелей fetch көбіне бөгеледі
- Репоға көшіру ЖОҚ (тапсырма шарты), бірақ runtime-кэш бұл ережені
  бұзбайды — файл репода жатпайды, тек уақытша кэште

Тәуекел: портал HTML құрылымы өзгерсе, парсер сынады — деградация fallback-қа
(§1.2 процедуралық текстура) құлауы керек, қате лақтырмауы керек.

### Қадам 3 — Панельге `map` мен мм-масштабты байланыстыру (~2 сағ, тәуекел төмен)

`components/PanelMesh.tsx`-те (шамамен 342-346 және 517/563 жолдар маңы)
қазіргі:

```ts
const grain = woodDecor ? grainTexture() : null
```

орнына (идея, нақты жүзеге асыру Scene/PanelMesh агентінің қолында,
себебі бұл файл дәл қазір басқа агентте):

```ts
const decor = catalog.materials.find((m) => m.id === panel.materialId)?.decor
const texture = decorTexture(decor) // жаңа хелпер: mapUrl болса жүктеп кэштейді, болмаса grainTexture() fallback
useEffect(() => {
  if (!texture || !decor?.mapSizeMm) return
  texture.wrapS = texture.wrapT = RepeatWrapping
  texture.repeat.set(extents.x / decor.mapSizeMm.x, extents.y / decor.mapSizeMm.y)
  texture.needsUpdate = true
}, [texture, decor, extents])
```

Неге: `floorTexture.ts:80`-дегі дәл сол үлгі («мм / физикалық span = repeat»)
қайталанады — жобада бұрыннан бар паттерн, тек декорға көшірілмеген.

Тәуекел: `BoxGeometry`-нің алты беті бірдей `map`-ты алады, ал панельдің
ұзындығы/ені/қалыңдығы үш басқа сан — repeat есебі қай бетке қатысты
екенін нақтылау керек (негізгі кең беттерге L×W, торцтарға қалыңдық×L/W).
Бұл — жүзеге асырушы агентке ескерту, толық шешім емес.

### Қадам 4 — Текстура бағыты (`grainAlongLength`) 3D-ге (~1-2 сағ, тәуекел орташа)

Идея: `panel.grainAlongLength` (немесе `cabinet.panelGrain[panel.id]`)
`false` болғанда, текстураны 90°-қа бұру:

```ts
texture.rotation = grainAlongLength ? 0 : Math.PI / 2
texture.center.set(0.5, 0.5)
```

не repeat.x/repeat.y-ды ауыстыру (`swap`) — қайсысы дұрыс нәтиже
беретінін нақты панельмен көзбен тексеру керек (BoxGeometry UV бағдары
бетке қарай өзгереді). Бұл — раскроймен 3D-ді алғаш рет БІР ақиқатқа
келтіретін қадам, сондықтан құжаттың ең маңызды түзетуі.

Тәуекел: орташа — UV бағыты geometry типіне (box vs extrude) қарай
өзгеше болуы мүмкін, екі жағдайды да сынау керек (`shape || tilted`
тармағы `PanelMesh.tsx:469` мен қарапайым `mesh` тармағы `526`-дан
бастап — екеуі де бөлек UV жолымен жүреді).

### Қадам 5 — Fallback сапасын жақсарту («болжам», ~1 сағ)

Барлық 500+ декорға бірден нақты сурет болмауы мүмкін (Қадам 0-дің
белгісіздігіне байланысты). Аралық шешім: fallback процедуралық
текстураны decor.kind/атауына қарай 2-3 түрге бөлу (ашық ағаш / қою ағаш /
бетон-текстура) — қазіргі «бәріне бір жолақ» дегеннен жақсырақ, бірақ
әлі де жалған екенін атап өту керек (клиентке «шамамен» деп көрсету).

### Қадам 6 — Өнімділік/сапа тазалығы (~30 мин, тәуекел төмен)

- `anisotropy = renderer.capabilities.getMaxAnisotropy()` (қазіргі қатаң
  `4` орнына, `grainTexture.ts:63`)
- Нақты сурет жүктелгенде декор бойынша `Map<mapUrl, Texture>` кэші (бір
  жобада бірнеше панель бір декорды қолданса, бір рет жүктеу)
- Үлкен суреттерді (портал 2000px беруі мүмкін) 1024px-ге дейін
  азайту/өңдеу — Қадам 2-нің сервер жағында жасалғаны дұрыс (клиентте
  емес)

түрінде жазған дұрыс, жобаның қалған стиліне сай.

## 5. Өлшенетін нәтиже

1. **Ажырату тесті.** Бір жобада екі «дуб» декорын (мыс. Kronospan K076 пен
   Egger W980) қатар қойып, скриншот салыстыру: қазір екеуі бір текстура +
   басқа түс; түзетуден кейін екеуі манифактураның НАҚТЫ фотосымен
   ерекшелену керек.
2. **Бағыт тесті.** Бір панельде `panelGrain` арқылы `'length'` → `'width'`
   ауыстырып, 3D-де текстураның 90°-қа бұрылғанын көзбен растау + сол
   панельдің деталировкадағы «Текстура» бағанымен (`cutList.ts:92`)
   салыстыру — екеуі енді сәйкес келуі керек.
3. **Масштаб тесті.** Бір декордың кіші панелі (мыс. 300×400 мм сөре) мен
   үлкен панелі (2000×600 мм бүйір) қатар тұрғанда, текстураның тайл
   өлшемі (пиксельде өлшенген «талшық аралығы») екеуінде БІРДЕЙ мм-ге сай
   болуы керек — үлкен панельде көбірек қайталану, кішіде азырақ, бірақ
   бірдей ТЫҒЫЗДЫҚ.
4. **Өнімділік тесті.** Chrome DevTools Performance/Memory: 500 декордың
   ішінен 5-6 түрлі декор қолданылған жобаны ашқанда, желі сұранысы
   (Network tab) сол 5-6 декордың суретіне ғана тең болуы керек (барлық
   500-ін алдын ала жүктемеу). Бұрынғы (fallback) күймен салыстырғанда
   GPU жады өсімі 5-6 текстураға (әрқайсысы ≤1024px) сай, шектен тыс
   болмауы керек.
5. **Регрессия тесті.** `npm test` — раскрой мен деталировка тесттері
   (`nesting.ts`, `cutList.ts`) өзгермеуі керек, себебі бұл жоспар ТЕК
   3D-көрініс қабатына тиеді, ядроға (`src/core`) физикалық есептеулерге
   тимейді (тек `Decor` типіне optional өріс қосылады).
